### Первоначальный анализ датасета
Датасет состоит из 301 строки и 9 столбцов, после удаления дубликатов получается 299 строк.
Пропущенных значений невыявлено. 

Целевая переменная Selling_Price имеет асимметричное распределение. Большинство автомобилей имеют цену до 10 lakhs, но присутствуют и дорогие экземпляры.

Ключевые факторы, влияющие на цену:

Наибольшее влияние: Present_Price (текущая цена) имеет самую сильную положительную корреляцию с ценой продажи (0.88).

Значительное влияние: Year (год выпуска) также сильно влияет на цену. Чем новее автомобиль, тем он дороже.

Слабое влияние: Driven_kms (пробег) и Owner (количество владельцев) показали слабую корреляцию с ценой, хотя и прослеживается тенденция к ее снижению с ростом этих показателей.

Было решено заменить признак "Год выпуска" на "Срок службы автомобиля", приняв за текущий год максимальное из представленных значений(2018).
 
При этом неинформативным признан признак количества владельцев, так как ненулевое значение он имеет только у 11 машин.

ИИС. Лабораторная работа № 3 — развёртывание ML-модели с FastAPI и Docker

Цель работы

Разработать REST API для предсказания стоимости автомобилей на основе ML-модели, зарегистрированной в MLflow в лабораторной работе № 2, и развернуть приложение в Docker-контейнере.

Реализация

Для создания REST API использован фреймворк FastAPI.

Основные файлы приложения:

* services/ml_service/main.py — FastAPI-приложение и обработка HTTP-запросов.
* services/ml_service/handler.py — загрузка MLflow-модели, подготовка входных данных и получение предсказания.
* services/ml_service/Dockerfile — инструкция по сборке Docker-образа.
* services/ml_service/requirements.txt — зависимости приложения.
* services/models/ — сохранённая MLflow-модель.

Реализованы два HTTP-метода:

* GET / — проверка доступности приложения, возвращает {"Hello": "World"}.
* POST /api/prediction — принимает характеристики автомобиля и возвращает предсказанную стоимость.

Интерактивная документация API доступна по адресу /docs.

Сборка Docker-образа

Из корневой папки проекта перейти в каталог приложения:

cd ~/mf_project/services/ml_service

Собрать Docker-образ:

sudo docker build -t car-price-api:1 .

Запуск Docker-контейнера

Модель хранится отдельно от Docker-образа и подключается в контейнер как bind mount с доступом только для чтения.

sudo docker run --rm -p 8001:8000 \
  -v "$(pwd)/../models:/models:ro" \
  --name car-price-container-v1 \
  car-price-api:1

После запуска приложение доступно по адресу:

http://localhost:8001

Документация Swagger UI:

http://localhost:8001/docs

Проверка REST API

Для проверки метода POST /api/prediction использован Swagger UI.

Пример запроса с параметром item_id=123:

{
  "Year": 2015,
  "Present_Price": 10.0,
  "Driven_kms": 30000,
  "Fuel_Type": "Petrol",
  "Selling_type": "Dealer",
  "Transmission": "Manual",
  "Car_Age": 11
}

Результат выполнения запроса:

{
  "item_id": 123,
  "predict": 7.005090242790106
}

# ИИС. Лабораторная работа № 4 — мониторинг ML-сервиса

## Цель работы

Реализовать мониторинг REST API для предсказания стоимости автомобилей с использованием Prometheus и Grafana.

## Реализация

В лабораторной работе № 4 выполнены следующие действия:

1. В FastAPI-приложение добавлена библиотека `prometheus-client`.
2. Реализован HTTP-метод `GET /metrics` для предоставления метрик Prometheus.
3. Настроен сбор метрик с помощью Prometheus с интервалом 5 секунд.
4. Настроен запуск сервисов через Docker Compose.
5. Подключена Grafana к Prometheus в качестве источника данных.
6. Создан дашборд для визуализации работы ML-сервиса.

## Основные метрики

- `prediction_requests_total` — количество запросов на предсказание с разделением по статусу выполнения.
- `prediction_duration_seconds` — время выполнения предсказания.
- `predicted_car_price` — последняя предсказанная стоимость автомобиля.

## Дашборд Grafana

Создан дашборд **Car Price Prediction — ML Monitoring**, содержащий шесть графиков:

1. Количество успешных предсказаний за 5 минут.
2. Среднее время выполнения предсказания.
3. Скорость обработки запросов (RPS).
4. Количество ошибок предсказания за 5 минут.
5. Предсказанная стоимость автомобиля.
6. Диапазон предсказанных цен за 15 минут.

Диапазон предсказанных цен определяется как разность максимального и минимального значений метрики, зафиксированных Prometheus за последние 15 минут.

## Запуск системы мониторинга

Перед запуском необходимо собрать Docker-образы ML-сервиса и генератора запросов.

Из корневой папки проекта выполнить:

```bash
docker compose -f services/compose.yml up -d
```

После запуска доступны следующие интерфейсы:

- FastAPI: http://localhost:8000/docs
- Метрики FastAPI: http://localhost:8000/metrics
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000

Для остановки контейнеров:

```bash
docker compose -f services/compose.yml down
```

## Результат

Реализована система мониторинга ML-сервиса, позволяющая отслеживать количество и скорость обработки запросов, время выполнения предсказаний, ошибки и результаты работы модели.

Работоспособность системы подтверждена отображением метрик в Prometheus и визуализацией шести графиков в Grafana.
